# 屏幕 4｜数据格式与模型真正看到的输入

## 原始实例：JSON

```json
{
  "evidence_label": "SIM_GEOMETRIC",
  "workpiece_id": "...",
  "layout_id": "...",
  "segments": ["曲线、位姿、长度、约束、前驱、资源"],
  "robots": ["基座、能力、工具、可用时间、初始状态"],
  "resources": ["类型、容量、可用时间"]
}
```

## 转换后的异构图

| 对象 | 当前特征维度 | 主要内容 |
|---|---:|---|
| Segment node | 39 | 几何、时间、能力、优先级、前驱/交接 |
| Robot node | 23 | 基座、工具能力、可用时间、初始状态 |
| Resource node | 7 | 类型、容量、时间窗 |
| Robot–Segment pair edge | 12 | 可行性、执行和转移代价 |

共有六类有向关系边。词表和标准化只在训练集拟合。

## 模型输出

每一步选择：

```text
a_t = (尚未分配的 atomic unit, robot)
```

最终输出：`segment_id、robot_id、order_index、planned_start/end、status、diagnostics`。

> **我这样讲：**  
> 数据落盘是版本化 JSON，进入模型后转换为 segment、robot、resource 三类节点和多类关系边。模型不是一次性对所有段独立分类，而是每一步从当前合法的“任务单元—机器人”pair 中选一个，所以前一步的分配会改变后面的负载、位置和资源状态。

# 屏幕 6｜方法：动态 Feasible-Pair Pointer

## 静态 decoder 的问题

静态方法同时计算所有 assignment logits 和独立 order score，不能根据前一步选择实时更新：

- 机器人负载和预计完成时间；
- 机器人最后位置和转移代价；
- 前驱是否已满足；
- 共享资源状态。

## Pair-Pointer 的变化

逐步选择 `(atomic unit, robot)`，每一步更新动态状态；不可达、工具不匹配、前驱未满足、已分配 pair 在 softmax 前设为 `-inf`。

### 此页直接展示已有方法图

```text
/public/home/v-chengwy/cjz/RL_credit-assign/Data-Calibrated-Safe-Residual-RL/reports/phase1_allocation/figures/a3_5_sealed_final_v1/method_architecture_dynamic_state.png
```

> **我这样讲：**  
> 这里的核心不是简单把分类器换成 attention，而是把构造过程改成自回归。每选择一个任务单元和机器人，就更新负载、位置、前驱和资源状态，再决定下一步。hard mask 负责排除当前明确非法的 pair；最终方案仍由不变的 scheduler 和 verifier 检查，所以网络不能靠 soft penalty 掩盖硬约束失败。

|---|---:|---:|
| Pair-Pointer，三seed平均 | **65.05%** | 0.4460 s |
| 相同hetero-GNN + static decoder | 40.28% | 0.00613 s |

95% group-cluster CI：**[+18.52, +31.48]**

> **我这样讲：**  
> 这里是当前结果最需要正视的地方。简单的 load-balanced 方法覆盖率略高，而且快很多；MILP 和 LNS 的覆盖率也更高。所以我不准备把论文写成“GNN 优于传统方法”，更稳妥的贡献是连续工艺异构约束图和 feasibility-aware autoregressive decoding。强求解器必须作为能力上界和工程参照。

# 屏幕 9｜最近 A4a 做了什么，为什么没有继续报结果

## 原问题

在完全相同 repair 算法和预算下，Pair-Pointer warm-start 是否比 static、load-balanced、MILP 和 cold start 更快达到可行解？

## 已经完成

- 全新 development/validation 数据；
- 统一 initializer adapter 和 identical repair；
- 六类难度、5,616 行唯一 validation 矩阵；
- targeted tests 21/21，非 frozen regression 147 passed；
- Slurm 所有任务正常完成。

## 但评测语义审计发现两个问题

1. 部分 MILP 失败后被替换为 load-balanced 状态，标签仍写 MILP；
2. fixed-time evaluator 没有保留截止时间前已经找到的可行 incumbent。

正式处理：

```text
A4A_PRIMARY_EVALUATION_INVALID_STOP
```

- 不修补后重跑同一 validation；
- 不生成 A4 frozen；
- 不用有缺陷的结果判断 Pair-Pointer warm-start 优劣。

> **我这样讲：**  
> A4a 的目的本来是回答学习初始化是否能帮助相同 repair。但唯一 validation 运行后发现评测器有两个语义问题。因为之前预注册要求零完整性失败，我把这次结果判为无效，没有修好后在同一 validation 上重跑。它不能证明方法差，只说明这个协议无法回答问题。这也避免了看到结果后反复调整评测器。


# 附录 C｜老师可能追问的简短回答

## 为什么还要 GNN，简单启发式不是更好吗？

当前不能证明 GNN 工程上更好。已确认的价值是动态 Pair-Pointer 相对 matched static decoder 显著提高可行构造能力。若后续不能体现规模泛化或求解器增益，论文应转向 solver/LNS，Pair-Pointer 作为消融。

## 模型输出的是路径吗？

不是。当前输出 assignment、机器人内顺序和代理调度时间；完整笛卡尔/关节路径属于 WP-B，尚未开始。

## Hard mask 是否保证真实安全？

不保证。它只保证当前 schema/oracle 定义的能力、工具、atomicity 和代理可行性，不等于连续碰撞安全证书。

## 为什么 A4a 不修好后重跑？

因为 validation 已被观察。修补后重跑会把 validation 变成开发数据。若未来继续，必须新协议、新 ID 和新 validation。

## 当前最稳妥的论文贡献是什么？

连续工艺段异构约束图、atomic-unit–robot Feasible-Pair Pointer、动态状态更新、hard mask、不变 scheduler/verifier，以及严格 matched-decoder 和 untouched task-group 评测。
