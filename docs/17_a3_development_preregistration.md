# A3 train/validation development preregistration

Status: **FROZEN BEFORE FEATURE FITTING OR MODEL TRAINING** (2026-08-10).

This document starts A3 without opening the v4 frozen-test or stress splits. It governs W9 graph/model foundations and W10 train/validation model development. It is not the final frozen-test evaluation protocol.

## 1. Scientific question and scope

A3 asks whether a hard-mask heterogeneous graph model can imitate a known-feasible A1-proxy assignment/order teacher and produce candidate plans that the unchanged A1 verifier accepts. It does not ask whether a GNN is globally optimal, collision-safe or physically executable.

Input is one v4 continuous-process allocation instance: ordered curve segments, robots, resources, analytic edge estimates, precedence/within-curve relations and hard feasibility masks. Output is a masked segment-to-robot assignment, an order priority per segment, a deterministic robot-local order and a candidate A1 schedule. Output is not a motion trajectory or control command.

## 2. Strict data access

- Fit vocabulary, numerical normalisation and model parameters on the 192 v4 train instances only.
- Use the 48 v4 validation instances only for loss/accuracy, candidate feasibility, proxy objective and checkpoint/model selection.
- Do not read, enumerate through a model loader, export labels from or compute any metric on v4 frozen-test/stress.
- The development workspace must contain only train/validation instance and witness directories. The loader must reject `frozen_test` and `stress` even if such a path is supplied.
- V2/v3 frozen results remain diagnostic history and cannot select A3 features or hyperparameters.

The isolated development export is stored under ignored
`outputs/phase1_allocation/a3_development_v1/data/`; it contains 192 train
instances, 48 validation instances and exactly their 240 witnesses. It is a
byte-preserving access subset of v4, not a new benchmark or split.

The teacher is the corresponding constructive witness plan. Train witnesses supervise assignment and within-robot pairwise order. Validation witnesses provide selection metrics only. They are feasible under the A1 proxy but were generated by a deterministic load-aware construction; they are not CP-SAT optima or real expert actions.

## 3. Frozen graph representation

Node types are segment, robot and resource. Segment features include analytic curve shape, position/direction/AABB, duration, priority, time-window, relation counts and categorical process/handoff semantics. Robot features include base pose, availability, speed, initial-joint summaries and train-vocabulary capability/tool/model encodings. Resource features include type, capacity and availability.

Relations are bidirectional robot–segment edges with oracle estimates and the hard mask, directed precedence/follow relations including parent-curve sequence, and bidirectional segment–resource usage. Capability, tool and kinematic-model vocabularies and every numerical mean/standard deviation are fitted on train only; unseen validation categories map to `<UNK>`.

## 4. Frozen model and decoder families

Development compares an edge MLP ablation, a two-layer relation-aware heterogeneous GNN and a two-layer graph Transformer, all with 64 hidden units. PointNet is excluded from this protocol. Pair logits are hard-masked before assignment loss or decoding.

The decoder assigns complete atomic allocation units, never individual members of same-robot/non-splittable groups. Unit logits aggregate member logits and a robot is eligible only if every member edge is allowed. Segment order scores are converted into a deterministic precedence-aware local order. The A1 scheduler and verifier are unchanged; no CP-SAT repair or A4 operation is allowed in this phase. A failed candidate remains failed.

Training uses assignment cross entropy plus teacher-forced within-robot pairwise order BCE with weights 1.0 and 0.25. Seeds, optimizer, learning rate, epochs, patience and tie-breakers are fixed in `configs/allocation/a3_development_v1.json`.

## 5. Development gates

W9 requires deterministic graph bytes, train-only vocabulary/normaliser provenance, node/edge permutation consistency, hard-mask enforcement, atomic-unit preservation, complete decoded coverage, same-seed determinism and teacher hash/verifier integrity. The registered smoke run uses a lexicographic, cell-balanced subset and is an engineering test only.

W10 uses all train/validation instances and all three seeds. Primary selection is validation verified-candidate coverage, followed by mean verified weighted proxy score, atomic-unit assignment accuracy and median inference runtime. Failed candidates receive no imputed quality score and remain in the feasibility denominator.

Before any frozen access, a new document must freeze the selected architecture/checkpoint rule, all seeds and budgets, baseline/repair policy, statistical comparisons and success/failure claims. A3 development results cannot retroactively alter the A2 v4 manifest or acceptance thresholds.

## 6. Evidence boundaries

All evidence is **SIM_GEOMETRIC**. A hard mask guarantees only registered edge-level exclusions; it does not guarantee joint scheduling or collision safety. A verified A1 plan is feasible only under the analytical geometric/timing proxy. No real production, robot execution, physical quality, sim-to-real or formal-safety conclusion is permitted.
